## 零、当前实现（2026-11-25 更新）

栏目已整合进 **V2 主站本身**，不再以独立站点呈现：

- 路径：`/learn`（学习中心）与 `/daily`（单页「上市公司 ESG 报告拆解」）均在 V2 应用内，共用 V2 的导航、品牌、sitemap 与 RSS。
- 单页：所有期拆解、阅读地图、评级表和四种平台的分发文案（小红书/公众号、微博、朋友圈/社群、LinkedIn）都集中在 `/daily`；旧 `/daily/<slug>` 301 到 `/daily#<slug>`，sitemap 只保留 `/daily`。
- V1：只在页脚保留一条入口，href 指向 V2 主站根路径；V1 后端未改动。
- 每日更新由一条命令完成，现有 08:00 定时任务直接调用：

  ```bash
  python -m v2.scripts.daily_update
  ```

  命令会从港交所公开证券名单中选一家尚未拆解的公司，抓取最新 ESG/可持续报告（或最近年报），
  提取章节页码，抓取新浪财经公开评级，生成 `v2/content/daily/<日期>-<代码>.json`。
  同一天已有文章时直接退出；已存在的文章只读不写；列表、sitemap、RSS 从目录实时读取。
  新一期写入后，正文与分发文案会自动出现在 `/daily`，无需再构建。

- 持久化（已落实）：Render 免费层是临时文件系统，重启即清空，所以不靠服务器磁盘存内容。
  `.github/workflows/daily-esg.yml` 每天 00:00 UTC（北京时间 08:00）运行上面的命令，
  用 `git add -f v2/content` 把新一期与评级快照提交回仓库并 push；Render 连着仓库时随 push 自动重新部署，
  新一期就进入线上 `/daily`。内容留在 Git 历史里，不依赖任何免费实例的磁盘。
  若 Render 未开自动部署，在仓库 Secrets 里加 `RENDER_DEPLOY_HOOK_URL` 即可由工作流主动触发。
  手动补跑见：Actions → 每日 ESG 报告拆解 → Run workflow。

## 一、先说结论

| 阶段 | 做法 | 为什么 |
| --- | --- | --- |
| 现在（本周） | **V2 主站部署**，栏目直接作为 `/learn`、`/daily` 路径上线；V1 页脚加**一条静态入口链接**（仅改 `web/index.html`，不动后端） | 不碰 V1 业务逻辑，风险最低；栏目与 V2 共用域名、导航和收录 |
| 2–4 周后 | 若收录与点击达标，升级为**同域反向代理**（`/learn`、`/daily` 挂到 V1 域名下） | 同域能继承 V1 的域名权重与已有外链，SEO 收益最大 |
| 暂不做 | 直接改 V1 后端加路由（方案 A） | 违反冻结约束，回归风险最高，收益与方案 C 接近 |
| 备用 | 静态导出到 GitHub Pages（方案 D） | 无冷启动，但域名分散、维护两套，长期不如 B/C |

一句话：**先用 B 抢时间，再用 C 拿权重；A 不作为选项。**

## 二、四个方案与取舍

### 方案 A：直接加在 V1（同域、同应用）

在 `app/main.py` 增加 `/learn`、`/daily` 路由，页面模板与内容放进 V1。

- SEO：最好。同域、同 sitemap、同 robots，内链权重全部留在主站。
- 工程：需要改 V1 代码、依赖与部署；V1 已冻结，任何改动都要回归测试。
- 风险：高。V1 同时承载采集、报告、润色等主流程，新增路由可能引入启动失败或静态文件冲突。
- 结论：**不做**。除非后续正式解冻 V1 并安排回归窗口。

### 方案 B：V2 主站部署（当前采用）

V2 作为主站部署（可与 V1 同一仓库、不同服务），栏目不单独建站，直接挂在 V2 的 `/learn`、`/daily` 路径下。例如 `https://esg-learn.onrender.com`（实际域名以部署为准）。

- SEO：与 V2 工具页同域，共用 sitemap、RSS 和导航；若后续要继承 V1 权重，再升级为同域反向代理。
- 工程：零改动 V1 后端；V2 已有完整路由、sitemap、RSS、结构化数据。
- 风险：低。V1 完全不受影响；V2 故障不影响主站转化。
- 成本：Render 免费实例有冷启动（约 30–60 秒），首屏体验一般；可用定时 ping 或升级付费缓解。
- 结论：**现在用它上线**，先验证内容与搜索需求。

部署要点：

```bash
# Render 新服务
Build Command: pip install -r requirements.txt
Start Command: python -m uvicorn v2.app.main:app --host 0.0.0.0 --port $PORT
环境变量:
  V2_SITE_URL=https://<你的V2域名>
```

`V2_SITE_URL` 用于 canonical、sitemap、RSS 的绝对地址。现在 `_site_base` 会优先读它，其次读 `X-Forwarded-Proto` / `X-Forwarded-Host`，所以在 Render 上不设置也能得到正确的 https 域名；只有换成自定义域名且代理头不可靠时才需要显式设置。

**部署前必须处理：V2 目前被 `.gitignore` 忽略。** 仓库根目录 `.gitignore` 第 27 行是 `v2/`，注释写着「V2 (Render only runs V1)」。因此直接连仓库新建 Render 服务，构建产物里不会有 V2 代码。二选一：

1. **强制纳入现有仓库（改动最小）**：
   ```bash
   git add -f v2/app v2/scripts v2/content v2/web
   git commit -m "feat: add V2 learning microsite"
   ```
   V1 的启动命令仍是 `python start.py`，不会运行 V2；只是部署包变大。
2. **拆成独立仓库（更彻底）**：把 `v2/` 复制到新仓库，单独连 Render。缺点是两套代码、两套依赖，后续同步成本高。

建议先用第 1 种，等方案 C 落地后再决定是否拆分。无论哪种，`v2/content/daily/` 与 `v2/content/ratings/` 必须一起提交，否则线上页面没有内容。

### 方案 C：同域反向代理（验证后升级）

保持 V1 域名不变，把 `/learn/*`、`/daily/*`、`/sitemap.xml`、`/robots.txt` 指向 V2。

两种实现：

1. **Cloudflare Worker / 边缘规则**（推荐）：按路径转发到 V2，不碰 V1 代码。需要自定义域名接入 Cloudflare。
2. **V1 增加一个极薄的代理路由**：只对 `/learn`、`/daily` 前缀用 `httpx` 转发。需要改 V1，但改动可控制在几十行，且不触碰业务逻辑。

- SEO：最好。所有内容与 V1 同域，sitemap 可合并，内链权重集中。
- 工程：需要自定义域名与代理配置；要处理缓存、超时、错误页。
- 风险：中。代理层故障会影响两个站点的内容访问。
- 结论：**B 验证后再做**。判断标准见第六节。

### 方案 D：静态导出进 V1 或 GitHub Pages

把 `/learn`、`/daily` 预渲染成静态 HTML，放到 `web/` 或 GitHub Pages。

- SEO：静态页速度快；但若放在 `/ui/learn` 这类子路径，URL 不干净、canonical 难统一。
- 工程：需要新增导出脚本；内容更新要重新构建。
- 风险：低，但维护两套发布流程。
- 结论：**只作为归档或备用**，不作为主路径。

## 三、V1 曝光：最小改动方案

V1 目前是流量入口，但处于冻结状态。要把流量导向 V2，至少需要一条可见链接。按风险从低到高：

1. **只改静态文件**：在 `web/index.html` 页脚加一条
   `<a href="https://<V2域名>/?utm_source=v1&utm_medium=footer&utm_campaign=daily-teardown">ESG 学习与每日拆解</a>`。
   不动 Python、不动接口、不动数据；回滚只需删除一行。
2. **不改 V1，只做外部渠道**：在 LinkedIn、小红书、公众号的简介与置顶内容放 V2 链接。缺点是 V1 站内流量无法直接导过去。
3. **同域代理后再加链接**：如果确定走方案 C，链接可以直接写 `/daily`，不需要跨域。

建议：**优先争取第 1 条的最小解冻**；若不允许，先用第 2 条跑两周，用外部数据证明栏目有效，再申请解冻。

**已执行（2026-11-25，最小改动）**：在 `web/index.html` 底部资源链接行加入

```html
<a href="https://esg-learn.onrender.com/?utm_source=v1&utm_medium=footer&utm_campaign=daily-teardown"
   target="_blank" rel="noopener">ESG 学习与每日拆解</a>
```

只改了静态文件，未动 V1 后端。`href` 先按本文档约定的 Render 服务名填写，指向 V2 主站根路径；V2 实际域名确定后，只需替换这一行链接，其他位置无需改动。

链接位置建议：

- 顶部导航：`学习中心`、`每日拆解` 两个入口，字号与现有导航一致；
- 页脚：加一行「ESG 学习方法与每日报告拆解」，承接搜索落地页；
- 不要在首屏主 CTA 上抢「免费诊断」的注意力，学习内容是拉新，不是替代转化。

## 四、SEO 与收录清单

V2 已内置：

- 每页唯一 `title`、`description`、`canonical`、OG/Twitter 卡片；
- 语义化结构：`header/nav/main/article/section/footer`，单页单 `h1`；
- JSON-LD：`Article`、`BreadcrumbList`、`CollectionPage`、`WebSite`；
- `/sitemap.xml`：只列 V2 首页、学习中心、5 条路径与单页 `/daily`（每期用锚点，不再单独成页）；
- `/robots.txt`：允许抓取，屏蔽 `/api/` 与 `/ui/index.html`，保留 CSS；
- `/daily/feed.xml`：RSS 2.0，每期一条，link 指向 `/daily#<slug>`，供阅读器与聚合工具订阅；
- 站内互链：每期正文 → 分发文案 → 相关学习路径，单页内用目录锚点互跳。

上线后要做的动作：

1. **Google Search Console**：添加 V2 域名属性，提交 `https://<域名>/sitemap.xml`。若用 URL 前缀属性，把 Google 给的验证 meta 加到 `v2/web/index.html` 的 `<head>`；若有自定义域名，优先用 DNS 验证。
2. **Bing Webmaster Tools**：可从 GSC 导入，或单独提交 sitemap；Bing 对新站收录通常比 Google 快。
3. **百度搜索资源平台**：提交 sitemap。注意 `onrender.com` 子域在百度的抓取与信任度有限；面向国内用户时，自定义域名与备案是长期解。
4. **IndexNow**（可选）：内容更新后 ping Bing/Yandex，缩短发现时间。
5. **RSS 分发**：把 feed 提交到 Feedly、Inoreader；在邮件签名与公众号文末放订阅入口。
6. **内链检查**：每篇文章至少链接 2 条学习路径与 1 篇其他文章；避免孤岛页。
7. **结构化数据校验**：用 Rich Results Test 检查 `Article` 与 `BreadcrumbList`，确保无错误。
8. **性能**：V2 页面为服务端拼装 HTML，体积小；上线后压缩 CSS、开启 gzip/brotli，关注 LCP。

不建议的做法：

- 关键词堆砌、批量生成同质页面；
- 用 JS 动态注入正文（搜索引擎可抓，但稳定性差）；
- 把评级字母写成「推荐」「买入」等投资建议；
- 复制报告原文大段内容（版权与重复内容风险）。

## 五、内容分发：一篇拆解，四种用法

每期文章发布后，按同一套动作分发，降低边际成本：

| 渠道 | 形式 | 重点 | 频率 |
| --- | --- | --- | --- |
| LinkedIn | 300–500 字观点 + 文章链接 | 港股 IR、ESG 经理、研究员；讲方法与边界，不承诺评级 | 每周 2 条 |
| 小红书 / 视频号 | 5–7 张卡片或 60 秒口播 | 中小企业主、转行者；用「一张图看懂」切入 | 每周 2 条 |
| 公众号 | 每周汇总 + 一篇深度 | 可复用文章主体，加站内导流 | 每周 1 篇 |
| RSS / 邮件 | 全文摘要 + 链接 | 从业者订阅，形成复访 | 每期 |

UTM 规范（统一小写）：

```
?utm_source=linkedin&utm_medium=social&utm_campaign=daily-teardown&utm_content=2026-11-25-aia
?utm_source=xiaohongshu&utm_medium=social&utm_campaign=daily-teardown&utm_content=2026-11-25-aia
?utm_source=v1&utm_medium=nav&utm_campaign=daily-teardown
```

canonical 不带 UTM，避免重复收录。V1 的转化链接反向带回 UTM，形成「内容 → 学习 → 工具」的闭环。

## 七、判断是否升级到方案 C

跑满 2–4 周后，看四个信号：

1. **收录率**：sitemap 中 ≥ 80% 的 URL 被 Google 收录；
2. **搜索曝光**：GSC 出现稳定的长尾词曝光（如「XX 公司 ESG 报告」「MSCI 评级 怎么看」），不要求短期大流量；
3. **站内行为**：文章 → 学习路径的点击率 ≥ 15%，文章 → V1 工具的点击有可识别的 UTM；

- **合规**：不构成投资建议、合规意见或评级结论；页面保留免责声明。
- **搜索作弊**：不做批量同质页、不做隐藏文字、不用虚假结构化数据。
